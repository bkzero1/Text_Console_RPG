# AsciiArtTest

## 상점 화면 AA 테스트

상점은 이미지 안에 글자를 굽지 않고, AA로 그린 장면 위에 콘솔 텍스트를 겹쳐 표시합니다. 따라서 보유 골드나 선택 표시를 매번 새 이미지로 만들지 않고 바꿀 수 있습니다.

- 배경: `resources/images/shop_background.png`
- 상점 주인: `resources/images/shopkeeper.png` — 흰 배경을 투명 처리하여 중앙에 배치
- 테이블: 별도 테이블 이미지를 쓰지 않고 `shop_background.png` 안의 원래 테이블 부분을 다시 덮어 표시
- 위치명·골드·메뉴: `TextRPGSource/ShopScreen.cpp`에서 콘솔 텍스트 오버레이로 출력
- 입력 문구: 기존 `Shop()` 함수의 `선택해주세요:`가 이미지 바로 아래에 계속 출력

상점 제목과 메뉴 이름은 기존 TextRPG의 `TEAM_3 TRPG SHOP`, `아이템 구매`, `아이템 판매`, `돌아가기` 문구를 유지합니다. 메뉴는 `DrawStaticImageText()`의 행 오프셋으로 기준 위치보다 4줄 아래에 출력합니다.

상점의 제목·메뉴 문구는 `TextRPGSource/main.cpp`의 `shopMenuText`에서 한 번만 정의합니다. `ShopScreen.cpp`은 그 문구를 전달받아 출력만 하므로, 메뉴 이름을 바꿀 때는 `main.cpp`만 수정하면 됩니다.

상점에서 `P`를 입력하면 상점주인 배치 모드가 열립니다. 상점주인 위를 마우스로 클릭·드래그하면 이동하고, `+/-`로 원본 비율을 유지한 채 크기를 조절할 수 있습니다. `S`는 `ShopLayout.jsonc`에 저장하고, `X`는 편집 전 배치로 되돌립니다.

배치 모드의 화면 맨 위에는 `해상도`, `세로 비율`, `대비` 슬라이더가 표시됩니다. 각 막대를 마우스로 누르거나 드래그하면 해당 값이 즉시 장면에 적용되고, `S` 저장 시 `ShopLayout.jsonc`에 함께 저장됩니다.

상점 배치 장면은 임시 PNG 파일을 저장한 뒤 다시 읽지 않습니다. 배경·상점주인을 메모리에서 합성한 직후 Braille AA로 변환하므로, 드래그할 때 발생하던 디스크 저장/재로드 지연을 제거했습니다.

상점의 연속 프레임은 매번 콘솔 전체를 지우지 않습니다. 이전 프레임의 Braille 행과 새 프레임을 비교해 달라진 행만 다시 출력합니다. 창 크기·AA 해상도·출력 위치가 바뀌는 경우에만 화면 정리가 한 번 발생합니다.

상점 일반 화면과 배치 모드 모두에서 상점주인이 저장된 기본 위치 주변으로 위아래 약 3, 좌우 약 1만큼 천천히 움직입니다. 이 움직임은 미리보기 전용이므로 저장한 배치값 자체는 바뀌지 않습니다. 일반 화면에서도 입력을 기다리는 동안 계속 움직이며, `1`·`2`·`0` 입력과 `P` 배치 모드는 그대로 사용할 수 있습니다.

상점 메뉴는 키보드 윗줄 숫자뿐 아니라 NumLock이 켜진 숫자패드의 `0`·`1`·`2`도 받을 수 있습니다. 숫자패드는 Windows에서 윗줄 숫자와 다른 키 코드로 전달되므로 둘을 따로 처리합니다.

전체 애니메이션 FPS는 `SceneConfig.jsonc`의 `frames_per_second` 하나로 관리합니다. 1~240 범위에서 설정할 수 있으며, 현재는 일반 게임 화면에 맞춰 `30`으로 설정되어 있습니다. 상점 일반 화면·배치 모드와 전투 테스트 렌더러가 이 값을 사용합니다.

상점에서 구매·판매 메뉴를 선택하면 AA 이미지의 끝 다음 줄을 비운 뒤, 기존 TextRPG의 목록과 입력 문구를 출력합니다. 따라서 기존 출력이 `0. 돌아가기` 메뉴의 오른쪽에 이어 붙지 않습니다.

구매·판매 목록이 길어 콘솔이 스크롤되더라도 상점으로 돌아오면 AA 화면을 한 번 새로 그립니다. 또한 `0. 돌아가기`는 가운데 정렬을 유지하면서도 `1. 아이템 구매`, `2. 아이템 판매`와 같은 시작 열에 맞춥니다.


상점 화면은 사용자가 직접 콘솔 창을 최대화한 뒤의 실제 행·열 수를 읽어 AA 해상도를 가능한 만큼 높여 출력합니다. Visual Studio 디버그 콘솔과 Windows Terminal에서는 프로그램이 창 최대화를 강제하면 입력 포커스가 꼬일 수 있으므로 자동 최대화는 사용하지 않습니다.

## 메인 메뉴 AA 사용법

메인 메뉴는 `resources/images/main_menu_day_final_candidate_v5.png`(낮)와 `resources/images/main_menu_night.png`(밤)를 컬러 Braille AA로 출력합니다. `1. 전투 / 2. 상점 / 3. 플레이어 정보 / 4. 처치 기록`은 이미지가 끝나는 바로 다음 줄에 가로 한 줄로 표시되고, 그 아래 줄에 `입력:`이 표시됩니다. 첫 전투를 마치고 처음 도착하는 마을 메뉴는 항상 낮입니다. 그 뒤 전투를 마치고 마을로 돌아올 때만 낮과 밤이 번갈아 바뀝니다. 상점·플레이어 정보·처치 기록 화면을 오갈 때는 시간대가 유지됩니다. 상점 창·랜턴, 길드 랜턴, 전투 길 횃불의 빛은 원본 PNG를 수정하지 않고 렌더링 순간에만 덧그려 천천히 밝아졌다 어두워집니다. 중심부는 더 크게 맥동하고, 주변의 작은 불티 도트는 1~2픽셀 범위에서 천천히 흔들립니다. 낮에는 은은하고, 밤에는 더 또렷하게 보입니다. 평소에는 조절 안내를 표시하지 않지만 개발 중에는 `P`를 누르는 즉시 상점·전투와 같은 `해상도`, `세로 비율`, `대비` 슬라이더를 열 수 있습니다. Windows 가상 키 코드를 읽으므로 한글 입력 상태에서도 `P`가 동작합니다. `S`를 누르면 `SceneConfig.jsonc`의 `main_menu_output_pixel_width`, `main_menu_character_height_scale`, `main_menu_contrast`에 저장되고, Enter 또는 Space를 누르면 메인 메뉴로 돌아옵니다.

일반 전투와 보스 전투는 시작 직전에 이전에 별도로 만든 AA 전투 화면을 엽니다. 따라서 캐릭터 생성 뒤의 첫 전투와 메인 메뉴 `1. 전투` 모두 같은 화면으로 진입합니다. 평소에는 장면만 표시되고, `P`를 누르면 슬라이더와 배치 모드가 나타납니다. `ESC`를 누르면 AA 화면만 닫히며 이어서 기존 `BattlePhase()` 자동 전투 규칙이 진행됩니다. GDI+ 이미지가 먼저 정리된 뒤 GDI+가 종료되도록 처리해 ESC 종료 시 접근 위반이 나지 않게 했습니다. 다음 단계에서 현재 턴, 실제 파티원, 실제 몬스터 데이터를 이 화면에 연결합니다.

전투 데모는 `SceneConfig.jsonc`의 이미지 파일명을 읽습니다. 파일명만 적혀 있어도 프로젝트의 `Resources/Images` 폴더를 자동으로 한 번 더 찾아보므로, 새 이미지는 해당 폴더에 넣고 파일명만 바꾸면 됩니다.

## 팀 공유용 정리 초안

완성 시 이 문서에 다음 항목을 확정해 공유합니다.

- 기본 TextRPG 코드와 AA 전용 어댑터의 경계
- 화면별 진입·복귀 흐름과 단축키
- `SceneConfig.jsonc` 및 이미지 교체 방법
- 전투 체력 바, 피해·회복 애니메이션, 자동·수동 공격 처리 방식

### 작업 완료 기준

구현 요청에서는 계획만 반복하거나 문서·데이터 구조만 추가한 뒤 완료로 보고하지 않습니다. 실제 동작까지 구현하고, 사용자가 실행해 확인할 수 있으며, 통합 프로젝트 빌드가 경고 0개·오류 0개인 경우에만 완료로 보고합니다.

시작 화면은 Enter 또는 Space를 누르면 흑백 1초를 유지한 뒤 컬러와 흑백을 네 번 더 번갈아 표시합니다. 점멸 중에는 `ENTER 또는 SPACE를 누르세요` 문구가 같은 위치에 유지되고, 마지막 컬러 프레임으로 바뀌는 순간 `1. 게임 시작 / 2. 종료` 메뉴로 즉시 교체됩니다. 마지막 두 번은 컬러 0.12초·0.08초, 흑백 0.08초·0.05초로 매우 짧게 점멸합니다. 컬러가 점점 자주 살아나는 방식이라 흑백 장면에 색이 스며드는 느낌을 줍니다. 시작 안내 화면과 `1. 게임 시작` 메뉴 화면 모두에서 숨김 키 `P`를 누르면 시작 화면의 점 농도·대비 슬라이더가 열립니다.

## 시작 화면 AA 사용법

시작 화면은 `TextRPGSource/StartScreen.cpp`에서 AA 모듈을 호출합니다. 기존 게임의 `main.cpp`는 게임 상태 전환만 담당하며 수정하지 않습니다.

현재 테스트 배경은 `resources/images/start_background_lowpoly.png`입니다. 이전 배경은 같은 폴더의 `start_background_morning.png`에 남아 있으므로, `StartScreen.cpp`의 파일명만 바꾸면 언제든 비교할 수 있습니다.

## 상점 화면 테스트 에셋

`resources/images`에 상점 화면 배치 모드용 이미지 세 장을 추가했습니다.

- `shop_background.png`: 컬러 상점 실내 배경
- `shopkeeper.png`: 흰 배경이 투명 처리되도록 고려한 상점 주인 상반신 이미지
- `shop_counter.png`: 상점 주인 앞에 배치할 나무 테이블 이미지

상점 화면의 진입점은 `TextRPGSource/ShopScreen.h`, `TextRPGSource/ShopScreen.cpp`입니다. 현재 `ShopScreen::Render()`는 컬러 상점 배경만 출력하며, 다음 단계에서 상점 주인 배치·저장·숨쉬기 연출을 추가합니다.

```cpp
// TextRPGSource/StartScreen.cpp
const bool didRenderBackground = AsciiArt::RunStaticImageTuner(
    L"Resources\\Images\\start_background_morning.png",
    false
);
```

시작 화면은 `RenderSavedStartScreenImage()`로 브라유(Braille) 점 방식 이미지를 한 번 출력합니다. 저장된 값으로 고정되어 슬라이더는 표시하지 않습니다.

배경 이미지는 콘솔의 왼쪽부터 출력하고, `ENTER 또는 SPACE를 누르세요` 및 메뉴 문구는 콘솔 전체가 아니라 실제 이미지 가로 폭의 가운데에 맞춥니다.

첫 화면에서는 흑백 배경 위에 `ENTER 또는 SPACE를 누르세요`만 `1. 게임 시작`이 표시될 위치에 출력합니다. Enter/Space를 누르면 같은 배경을 컬러로 한 번 다시 그린 뒤 `1. 게임 시작`, `2. 종료` 메뉴를 표시합니다.

이미지의 원본 크기나 가로세로 비율이 바뀌어도 출력 시 실제 이미지 가로 범위를 다시 계산합니다. 메뉴의 가로 위치는 이미지 가운데에 맞추되, 세로 위치는 콘솔 화면 기준으로 유지합니다. 선택 뒤 기존 TextRPG 출력은 이미지가 끝난 뒤 두 줄을 비운 다음 줄부터 시작합니다.

- `점 농도`: 높을수록 밝은 영역에도 흰 점이 많이 남습니다.
- `대비`: 높을수록 밝고 어두운 영역의 차이가 커집니다.

저장되는 설정은 아래 두 항목입니다. 값 범위는 모두 `0~1000`입니다.

```jsonc
// SceneConfig.jsonc
"start_screen_ink_density": 0,
"start_screen_contrast": 850,
```

## 공용 함수

- `AsciiArt::RenderStaticImage()`: 이미지를 한 번 출력합니다. 기본 표현 방식은 브라유 점 방식입니다.
- `AsciiArt::RenderSavedStartScreenImage()`: `SceneConfig.jsonc`에 저장된 시작 화면 점 농도와 대비로 이미지를 출력합니다.
- `AsciiArt::RunStaticImageTuner()`: 시작 화면용 마우스 조절 화면을 출력하고, 저장과 계속 진행 입력을 처리합니다.
- `AsciiArt::ClearScreen()`: 다음 장면으로 전환하기 전에 현재 AA 화면을 지웁니다.
- `AsciiArt::ClearBottomRows()`: 화면 아래의 예약된 안내/슬라이더 줄만 지웁니다.
- `AsciiArt::DrawCenteredTextOnClearPanel()`: 텍스트 주변을 공백으로 덮은 뒤 중앙에 출력합니다. AA 배경 위에서 메뉴 문구가 묻히지 않을 때 사용합니다.

## 코드 예시 작성 규칙

문서에 C++ 코드 예시를 추가할 때는 코드 블록의 첫 줄 주석으로 해당 코드가 들어가는 파일 경로를 표시합니다.

## 빌드 품질 기준

이 통합 테스트 프로젝트는 수정 후 전체 다시 빌드했을 때 `경고 0개 / 오류 0개`를 유지하는 것을 기준으로 합니다.

- `==`는 두 값이 같은지 비교할 때 사용하고, 값을 바꿀 때는 `=`를 사용합니다. `InventorySlot::Clear()`에서는 비교 연산자를 대입 연산자로 수정했습니다.
- `vector::size()`의 반환형은 `size_t`입니다. 게임에서 `int` 계산이 필요한 곳은 `static_cast<int>()`로 변환 의도를 명시했습니다.
- 보스 능력치의 1.5배 계산은 최종 자료형이 `int`이므로 `static_cast<int>()`로 소수점이 버려짐을 코드에 드러냈습니다.
- 몬스터 풀의 축소 조건은 현재 개수가 목표보다 클 때만 삭제하도록 수정했습니다.

원본 `Text_Console_RPG` 프로젝트는 변경하지 않았고, 위 수정은 `AsciiArtTest/TextRPGSource`에 복사해 둔 통합 테스트용 코드에만 적용했습니다.
